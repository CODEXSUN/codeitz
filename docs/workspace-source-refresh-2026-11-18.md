## Audit findings that still require review

The sync/data comparison passed. This is not a claim that every app has a complete approved coding blueprint or implemented business functionality. Source-derived missing information remains unselected rather than invented. New module definitions are drafts; previously reviewed descriptions and statuses are retained.

The Blueprint checker reports **948 review items** on each matching inventory. Main categories:

- 446: Required detail is missing.
- 298: Define a JSON schema; use {} explicitly when no fields are needed.
- 74: Confirm the owned PostgreSQL schema.
- 72: Choose app, tenant or master data ownership.
- 49: Define at least one API, action, event or table before coding.
- 3: Table name must have one owner in this project.
- 2: Choose the primary key fields.
- 1: Choose a supported PostgreSQL type.
- 1: SQL type must match the field type.
- 1: Confirm the SQL type, including length or precision when required.
- 1: Add project modules before coding.

These include undocumented request/response/permission choices and module ownership/schema selection, web-only/scaffold modules, master/tenant table-name reuse in Platform, and one native BIGINT source type not supported by the current exact-type editor. Billing receipt/payment allocation migrations do not declare a primary key; the inventory records that source fact instead of inventing one. Composite FK/unique/check constraints are retained in table descriptions; a single field reference cannot encode all composite relationships.

The governance source audit also reports **two UIUX structure findings**: missing `contracts` and `src/api/modules`. UIUX is currently implemented as a web gallery without that backend structure. No folders or central rules were changed to conceal this mismatch. It needs a separate architecture/governance decision.
